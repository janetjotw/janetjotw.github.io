A Tech Writer and a User Advocate validating the product even before I write about it! I work with writer and developer toolsets all along exploring ways to publish content. I have had the opportunity to deliver technical and nontechnical docs for a wide audience: developers of the enterprise platform and customers. 

My previous work in a startup gave me the potential to immerse myself, innovate and evolve in my roles: Technical docs both hardware and software, API Reference documents including API Use Cases, Zendesk-KB and FAQs, Microservices, working on small software code snippets, Project Manager for the SOC2 compliance, etc. to name a few. Through this page, I aim to provide a summary of my execution of writing tasks and the tools used as a Technical Writer.

## 
Roles and responsibilities

- Collaborate with the CTO, SVP Customer Success, firmware engineers, developers, product managers to understand the product and architecture. Collect requirements, understand the scope, and obtain information to create writing deliverables.

- Write high-quality accurate, technical content to effectively communicate complex information clearly and provide a rich user documentation experience.

- Lead and manage documentation projects from requirements gathering, planning, writing, testing, and publication.

- Collaborate and provide guidance and support to the Customer Success Operations Team with docs and KBs.

- Run and execute test applications, perform QA that helps enhance product writing, best practices for integrations, API Reference document, how-to, Quick Start, and User Guides.

## Tools

Markdown, Asciidoc - Getting Started, Tutorials, and Quick Started Guides

Confluence - User Guides, Application Guides, API Use Cases

Microsoft Office 365 - General product and device IoT integration docs

VS Code Editor for integration with GitHub

Swagger, Postman - API documentation, validation and hosting

Apollo GraphQL Playground - GraphQL API

Zendesk - KBs.
